# 起因
##### 众所周知，Fedora 默认安装会抽出2GB的ext4分区作为/boot挂载点
这本身没啥问题
直到大前天，也就是8月11号
当时闲着没事干，觉着这2GB太过臃肿，想着缩小后后还能省下一点空间
于是做出了令我后悔的举动

# 经过
说干就干，我重启进入 LiveCD
很快啊，
把 /boot 缩到了 800MB。
经过预估，这个大小刚好足以存下各种内核以及initranfs
##### 注意此时没有发生任何事情，如果此时收手，我大概率不用多浪费两天的时间
然而，那时的我不这么觉得
由于boot分区位于整块硬盘的前段，使用btrfs的根分区在后段
调整完boot后，中间空出来了1.2GB的空间
##### 正所谓眼不见心不烦，这1.2GB空着就空着，但是如果这1.2GB不分配到根分区，那我调整boot分区就没啥意义了(事实也确实是这样)
然后，我就使用KDE分区管理器尝试把1.2GB挪给根分区。然而，我没有做任何的备份(我也想不通为啥不备份)
就这样，啪的就开始分区了，显示要半个多小时，我甚至还悠闲自在的刷视频去了

# Boom!
半小时过去了，没有意外啊，直接炸了
btrfs变成了“未知文件系统”
分区表还在，但是文件系统炸了
![表情](/images/archive/Pasted%20image%2020260813231636.png)
尝试使用：
```
btrfs rescue super-recover
```
通过超级块恢复文件系统
然而，超级块丢了，
备份超级块也全丢了

再次尝试使用
```
btrfs restore
```
绕过超级块，直接读取文件树
然而，文件树也成功地没掉了

这下慌了
然后就是各种问AI
甚至派Opencode坐阵修了2小时
问了Deepseek各种各样的问题

结果是：
![文件树丢失](/images/archive/Screenshot_20260810_195033.webp)
哇实在是太棒了
我们的文件树丢了哈哈哈

当时感觉自己也是个神人
风险操作不备份就算了，明知道恢复不了还找Opencode修了这么久，还没修好

# 最后
然后就没有然后了
只有重装更划算
![重装系统](/images/archive/Screenshot_20260810_194909.webp)
这次倒是学聪明了，将/boot /home /都设为了btrfs子卷，看着不那么难受，减少空间焦虑了属于是
数据到是没太大问题，因为我碰巧有几天前的备份。碰巧那几天更改的也就只有项目文件夹，这些在NAS和Github上都有备份(备份的好处hhh)
不过，系统设置一类的，以及一大堆软件包算是白布置了，于是我花了2天的时间把它们调回来...

# 友情提醒
操作分区一定一定一定要备份
数据无价！
